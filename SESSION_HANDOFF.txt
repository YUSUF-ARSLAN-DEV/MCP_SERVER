3.2 Untouched items from ISSUES.txt (full detail there, this is just the list):
    - No intent retirement: a flow intent that's simply a wrong guess (e.g. clicking "Setting" on the
      aljazeera home page does nothing - confirmed live earlier this session) gets re-attempted every run
      forever. No mechanism exists to notice "this has failed N runs in a row, stop retrying it."
    - intents/expand's own LLM prompt path was never audited for the same "doesn't explicitly instruct a
      click before describing the result" class of bug that was found and fixed in generator.py's
      _compact_primary_flow (commit eb37136). It may or may not have the same gap - not checked.
    - No regeneration caching - `generate` rewrites every page's test via a fresh model call every run,
      even for an unchanged page.
    - flows-verify stage is still single-threaded. Deliberately not parallelized this session: it shares
      one Playwright browser object across a mid-loop session-refresh (ensure_session, called when a
      flow's session expires mid-verify) and a nested try_other_options closure that also reuses that same
      browser - parallelizing this safely needs that session-refresh path to be made thread-safe first
      (a lock around the refresh + re-read of the resulting storage_state file), not a blind copy of the
      generate-stage ThreadPoolExecutor pattern.
    - Duplicate representation: the same user journey can exist as both an explorer-probed "primary flow"
      page-level test AND a separate intents/expand/verify/flowgen flow. Both existed side by side for the
      aljazeera country-search case earlier this session.
    - The .env SITE/SEED_URL shared-mutable-state hazard itself was never actually fixed at the
      architecture level - this session worked around it repeatedly (by constructing Settings(site=...,
      seed_url=...) explicitly in one-off scripts instead of relying on .env) rather than fixing it, since
      .env is actively shared with the user's own concurrent terminal usage and editing it directly during
      this session would have risked disrupting runs the user had going at the time.

5. THINGS TO KNOW ABOUT THE ENVIRONMENT
====================================================================

- .env's SITE/SEED_URL changes frequently - the user runs multiple pipeline invocations against different
  sites (sat-stg.aljazeera.tv, www.saucedemo.com, the-internet.herokuapp.com) concurrently in their own
  terminals. ALWAYS check current .env state (or bypass it via explicit Settings(site=..., seed_url=...)
  construction) before assuming which site a bare CLI command will target.
- This repo is split across two agents by explicit user instruction: this work is scoped to
  website_test_pipeline/ and tests_python/ only. A separate agent owns api/ (FastAPI job queue, frontend,
  backend, deployment). Never touch, stage, or commit files under api/.
- pytest-xdist was added as a dependency this session (pyproject.toml) and is installed in the current
  environment.
- Windows console (this Bash/PowerShell setup) frequently mis-renders Unicode (Arabic text, the "…"
  ellipsis character) as "�" when printed directly - this looked like real data corruption twice this
  session and was NOT (confirmed both times by checking the actual Unicode code point, not the printed
  text). Always verify a "corruption" claim against the real code point or by writing to a file and
  reading it back, never trust what prints to this terminal directly for non-ASCII content.
